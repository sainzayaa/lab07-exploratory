## Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь Fed-Ex ба Couch Potato байсан: Fed-Ex-ээр нэмэх, хайх, устгах замыг дагахад «Нийт ном» тоолуур (BUG-01) ба том/жижиг үсэг ялгадаг хайлт (BUG-04) илэрч, Couch Potato-ийн хоосон оролтоор заавал бөглөх талбарын шалгалт байхгүй байгаа нь (BUG-03) тод харагдсан. Saboteur аялалаар терминалаас буруу JSON илгээхэд API нь 400 биш 200 OK буцаадаг (BUG-02) нь илэрсэн бөгөөд энэ нь UI-аас харагдахгүй цорын ганц согог байлаа. Supermodel аялал (өнгө, урт текст) тусдаа согогийн тайлан өгсөнгүй, гэхдээ урт гарчиг оруулахад хүснэгт тэлж байсныг тэмдэглэлд тэмдэглэсэн. Session-ийн тэмдэглэлд Он талбарт 987 ба `abc` оруулахад ном нэмэгдэж, `abc` нь NaN болсон, ижил ном давхардаж нэмэгдсэн гэсэн ажиглалтууд бас байсан бөгөөд тэдгээр нь Couch Potato-ийн хүрээнд олдсон ч цагийн хязгаартай тул тусдаа тайлан болгоогүй, 4 согогийг шинэ апп дээр баталгаажуулахыг чухалчилсан. Charter-ээс бүрэн гадуур санамсаргүй согог олдсонгүй. Шалгагдаагүй үлдсэн нь «Хуучин хувилбар» линк болон бусад хуудас, Устгах үйлдлийн дараах мессеж, API-ийн бусад хүсэлтүүд (GET, DELETE), өөр браузер, эдгээр нь дараагийн session-ийн charter болно. Lab 1-ийн Playwright автомат тестээр дөрвөн согог бүгд баригдах байсан, учир нь тус бүр спецификацийн тодорхой дүрмийг зөрчдөг: хүснэгтийн мөрийн тоог «Нийт ном»-той тулгах, хоосон маягт илгээж ном нэмэгдээгүйг шалгах, `clean` гэж хайж үр дүн байгаа эсэхийг шалгах, API-д буруу JSON илгээж 400-г шалгах. Зөвхөн хүний нүдээр олдох нь харагдах байдлын асуудлууд (урт текстэд хүснэгтийн байршил, өнгө, мессежийн утга зүй), мөн спецификацид бичигдээгүй "энэ нь буруу санагдаж байна" гэсэн мэдрэмж. Миний дутагдал нь session-ийн явцад цагтай `note`-ыг тогтмол хөтлөөгүй, ихэнх ажиглалтыг дараа нь санахаар бичсэн явдал, дараагийн session-д эхнээс нь тогтмол тэмдэглэнэ.
